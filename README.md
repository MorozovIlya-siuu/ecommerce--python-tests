# E-commerce Python Tests

Лабораторная работа №3 по дисциплине "Тестирование ПО".

## Ответы на вопросы

### 1. Какие события активируют пайплайн?
Пайплайн активируется событиями `push` и `pull_request` в ветки `main` или `master`.

### 2. Будет ли пайплайн запускаться при изменении только README.md?
Да, будет, так как триггер настроен на любое изменение в ветке. Чтобы избежать этого, можно добавить `paths-ignore: ['**.md']`.

### 3. Как указывается установка зависимостей?
В файле `ci.yml` в секции `steps` через команду `run`: `pip install -r requirements.txt`.

### 4. Как настроить запрет на слияние, если тесты упали?
В настройках репозитория: Settings → Branches → Branch protection rules → выбрать ветку `main` → поставить галочку "Require status checks to pass before merging" → выбрать job `test`.

### 5. Всегда ли нужно 100% покрытие тестами?
Нет. Оптимальный промышленный стандарт — 80-90%, при котором покрыта вся бизнес-логика и граничные случаи. Стремление к 100% часто приводит к бессмысленным тестам для тривиального кода.

### 6. Какой стек технологий используется?
- Язык: Python 3.12
- Фреймворк тестирования: pytest
- Измерение покрытия: pytest-cov
- CI: GitHub Actions (YAML)
